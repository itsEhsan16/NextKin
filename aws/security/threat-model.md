# Threat model

**Version 0 · 2026-10-10 · owner: backend lane A**

This is the STRIDE model for the NextKin backend. It is task P0-05 of
`doc/ImBackendImplementationPlan.md`. Every threat names the plan task that mitigates it, so a
threat with no task is a gap.

**Re-read at every phase exit (P0–P13) and at every Connect item (X-01…X-15).** Each time, add rows
for anything new, change a row's status when its task proves the mitigation, and record the review in
the log at the bottom.

**Status values:**
- `open`: no mitigation is built yet.
- `built`: the mitigation exists, but its done-when has not passed.
- `proved`: the done-when passes in CI or as a written drill.
- `cloud`: provable only once its X item lands.

STRIDE letters, used in the tables: **S** spoofing · **T** tampering · **R** repudiation ·
**I** information disclosure · **D** denial of service · **E** elevation of privilege.

## Assets

| Asset                                                            | Why it matters                                                                     |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Resumes, profiles, uploaded documents                            | Sensitive personal data under GDPR, the Australian Privacy Act and CCPA (spec §8.5) |
| Contact details (email, phone, address)                          | Must never reach an AI provider (G5)                                                |
| Sessions and tokens                                              | Whoever holds one is the user                                                       |
| Quota and entitlements                                           | Real money: AI spend and paid plans                                                 |
| Scores, ledgers, provenance                                      | The product's promise of true numbers (G13–G18)                                     |
| Provider keys (AI, job boards, payments)                         | Abuse costs money and breaks provider terms                                         |
| Audit log                                                        | Evidence of what admins did                                                         |

## Trust boundaries

```
 [browser] ──cookie──┐                           ┌──▶ [AI providers]      (B4)
 [phone]  ──bearer───┼─(B1/B2)─▶ [web/API] ──(B3)──▶ [PostgreSQL / Valkey]
                     │               │ outbox ─▶ [queue] ─▶ [worker] ──┼──▶ [job boards, payments, email]
 [client] ──presigned POST/GET──(B5)──▶ [object storage] ◀────────────┘
 [payment provider] ──webhook──(B6)──▶ [web/API]
 [admin browser] ──admin session + TOTP──(B7)──▶ [web/API /admin]
```
